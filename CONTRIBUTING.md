# Contributing

This repository publishes the text of *Sapiens Novus — Constitutio Intermundia*, Public Release v1.x. The file is [`sapiens-novus.md`](sapiens-novus.md).

A change merged here updates that public text under the [GNU General Public License v3.0](LICENSE). It does not etch Root, move an Axiom, or stand in for the instrument's own amendment gate. That gate is the room **V. Modularity and Amendment** under **I. PRIMA**. Read it before you propose a change that touches an Axiom, the Oracle, the Ne floor, Neutralization, VCI weights, or the Protected-List.

The text names no personal author and no contact address. Use issues and pull requests on this repository.

## Critique

Open an issue with the critique template.

Name the room. Quote the clause. Say what fails: a meter the clause cannot meet, a contradiction with a named room, or a term the Glossary does not lock. Tone is not the charge. A critique that only dislikes the aim will be closed.

## Amendment

Prefer an issue before a pull request when the change is still a question. Open a pull request when you have replacement text.

In either place:

- Name the room (the heading, or the bold room title such as `II.10 Sex, Pairing and Legal Form`).
- Quote the current wording.
- Give the proposed wording in full. Do not leave the diff to be guessed.
- Say which meter, contract, or named failure the change answers.
- Say whether the proposal touches a Root-locked item. If it does, say so in the first line. Do not reclassify a locked item as a module inside the patch.

Grief, rage, love, and offense do not amend. The file says that. A pull request that only vents will be closed.

Keep the author's words where you are not changing them. Do not reword a room in order to smooth it. A formatting fix is welcome when Markdown renders the existing words wrongly (a broken heading, table, list, fence, or escape). State the rendering fault in the pull request. Do not ride a wording change in on a formatting fix.

## Forks

Forks are welcome. The work is GPL-3.0. If you distribute a modified version you must:

- Keep the license, and license your changes under GPL-3.0 as well.
- Mark the version as changed, so a fault in the fork is not attributed to this text.
- Leave this repository's name, and the claim of the human-terran original, off a fork that has diverged.

A fork is not the official text.

## What does not belong here

Build scripts, a website, and continuous integration are out of scope unless a later maintainer asks for them. The published artifact is the Markdown file.
